# FFmpeg Android integration status

## Source and license review

- Candidate source: upstream `FFmpeg/FFmpeg`, release tag `n8.1.3`, commit `1041abdc962f4cc4f394aa8de9dc5236c0c3b9e7` (tag resolved from the GitHub mirror on 2026-10-22).
- The release's `LICENSE.md` says the default build is LGPL v2.1 or later; GPL components are opt-in through `--enable-gpl`. The Android build keeps GPL/version-3 and nonfree options disabled, retains the pinned source and LGPL notice, and packages build metadata.
- `tools/build_ffmpeg_android.sh` pins the source and NDK `27.2.12479018`, builds arm64-v8a/API 24 shared libraries, enables JNI plus FFmpeg's H.264/HEVC MediaCodec decoders, and checks the generated configuration. The script's shell syntax and native host tests pass locally; this sandbox has no Android SDK/NDK, so Android compilation must be verified by CI.
- The Gradle task `:app:buildFfmpegAndroid` is wired before Android pre-build/native compilation. It provides the FFmpeg headers/libraries to CMake and packages the shared libraries, `COPYING.LGPLv2.1`, and `FFMPEG_BUILD_INFO.txt` into the app.
- Build products are kept under `app/build/ffmpeg-android`; the pinned source checkout is retained between builds. Marker files protect the private build and install-prefix directories, and the script recognizes the expected Gradle-cached prefix layout only under the default app build path. JNI libraries and notice assets are overwritten in place (not recursively deleted); markers from earlier script revisions are removed so they are not packaged.
- The previously inspected EkinStrop prebuilt remains unselected: its advertised minimum API 28 conflicts with this app's minSdk 24, and its inspected repository did not provide a reproducible binary build recipe.

## Playback and grading status

- `FFMPEG_NATIVE` is a distinct playback engine and does not replace ExoPlayer/Media3 or LibVLC. The native JNI path demuxes a file descriptor with FFmpeg, tries Android MediaCodec for H.264/HEVC, falls back to an included software decoder when available, and renders video to a `TextureView` surface. ExoPlayer remains responsible for source audio.
- Standard clips can use the FFmpeg route explicitly. For live color grading, the editor temporarily routes supported non-MCRAW sources through the Media3 GPU effect graph, then restores the requested engine. MCRAW uses its C++ Bayer renderer for supported exposure, white balance/tint, primary wheels, and color-balance controls; curves, HSL, LUTs, and advanced effects remain visibly unsupported on that route.
- The shared Media3 preview/export effect path renders supported curves. Export validation rejects unsupported layers, animation, and effects instead of silently dropping them.
- **Build verification:** GitHub Actions run `39800198201` passed Android Kotlin/native CMake compilation, JVM tests, C++ host tests, and FFmpeg build-script syntax on commit `dbb3357`, after catching and fixing two JNI compile errors. The first gated APK run (`39802315219`) passed those checks but failed during `:app:assembleDebug`; the downstream APK license check, checksum, and publishing steps were skipped. The first failure annotation omitted the specific Gradle exception, so the workflow now includes the full APK-assembly log tail on the next retry. It will also verify MotionCam Apache license/notices plus FFmpeg LGPL notice/build metadata inside the APK before publishing. Runtime playback, source-format coverage, audio synchronization, and device behavior have not been tested here; the user will perform device testing.
- Do not claim that all codecs, HDR/10-bit media, MotionCam files, or the previously reported 4K 10-bit HLG sample work without examining the exact media metadata/sample and device logs. No test APK has been generated or shared yet.
